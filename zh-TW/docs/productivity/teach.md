## 它做什麼

`teach` 把你執行它所在的目錄變成一個常駐的教學工作區，並以簡短、自成一體的 HTML 課程，透過許多次 [session](https://www.aihero.dev/ai-coding-dictionary/session) 教你一個主題。

它不是用[模型](https://www.aihero.dev/ai-coding-dictionary/model)已經知道的東西來教。它把[參數化知識（parametric knowledge）](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)視為不可信的。在教學之前，它會找出高可信度的資源、把它們記錄在 `RESOURCES.md` 中，並在每一堂課程中引用它們。它也是[有狀態的（stateful）](https://www.aihero.dev/ai-coding-dictionary/stateful)。使命、資源、課程以及你學到了什麼的紀錄，全都以檔案的形式存在目錄中，所以下一個 session 是從那些檔案接續，而不是從上一段對話殘留的東西接續。

## 何時使用

你透過輸入 `/teach` 來觸發它；[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不會自己去用它。

當學習本身就是專案時使用它：一種語言、一個框架、一個你剛加入的程式碼庫、瑜伽、shader、一張證照。它不是用來順帶解釋一件事的工具。

| 你想要什麼 | 使用什麼 |
| --- | --- |
| 在幾週內學習一個主題，而且每次 session 都會累積 | `teach` |
| 在你已經在的 session 中解釋一個概念 | 直接在那個 session 中問 |
| 因為 agent 上一則訊息沒被理解，而讓它重新說明 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨利你已經有的思考，而不是取得新的素材 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一個背景 agent 去讀[第一手資料](https://www.aihero.dev/ai-coding-dictionary/primary-source)，並留給你一份附引用的文件 | [research](https://aihero.dev/skills-research) |
| 學習在拷問中途出現的某件事，而不讓[拷問](https://www.aihero.dev/ai-coding-dictionary/grilling)偏離軌道 | 用 [handoff](https://aihero.dev/skills-handoff) 轉到一個教學工作區，然後在那裡用 `teach` |

## 前置條件

`teach` 建立的是一個目錄，而不是產出一個檔案，而且這個 skill 預設每個工作區只有一個使命，所以在一個你願意交給單一主題的地方執行它。讓它遠離你正在工作的專案。一個獨立的 repo 是最好的家，比全域的 `~/.learnings/` 資料夾或工作中的專案本身都好。一個專用的 repo 也讓你可以 commit 課程，團隊就是這樣分享它們的。

會在那個目錄中累積的東西：

| 路徑 | 存放什麼 |
| --- | --- |
| `MISSION.md` | 你為什麼要學這個。其他每一個檔案都依賴它。如果它不存在，`teach` 做的第一件事就是訪問你，直到它存在為止 |
| `RESOURCES.md` | 它用來教學的、經過審核的來源，分成 Knowledge（知識）與 Wisdom（智慧，社群） |
| `lessons/*.html` | 有編號的課程：教學的主要單位 |
| `reference/*.html` | 壓縮過的速查表、演算法、詞彙表：你會回頭查的文件 |
| `learning-records/*.md` | ADR 風格的筆記，記錄你已經證明學會的東西，用來決定接下來教什麼 |
| `assets/*` | 可重複使用的元件，從一份共用樣式表開始，讓課程看起來像一套完整的課程 |
| `NOTES.md` | 你表達過的教學偏好 |

關於這份清單有兩點說明。詞彙表適合大多數主題，但這個 skill 附帶了一份 `SKILL.md` 已經不再連結的 `GLOSSARY-FORMAT.md`，所以只有在你要求時才會得到一份（[issue #559](https://github.com/mattpocock/skills/issues/559)）。這一切都會落在你執行 `/teach` 的那個目錄中。

## 儲存強度，而不是流暢度

要用來思考的詞是**儲存強度（storage strength）**：長期保留，相對於**流暢度（fluency）**，也就是那種閱讀時感覺像精通、一週後就消失的當下回想。`teach` 透過合意困難（desirable difficulty）建立前者：提取練習、間隔、交錯。知識優先。在那個階段困難對你不利，因為它會用掉你理解所需的工作記憶。接著 `teach` 透過一個緊密的回饋迴圈來操練技能，而在那個階段困難就是工具。

有兩件事決定你會被教什麼。**使命**（你想要這個的具體現實理由）是每一堂課程的基礎。沒有它，課程就會變得抽象，也沒有任何東西能決定接下來要教什麼。根據使命與學習紀錄，`teach` 會在你的**近側發展區（zone of proximal development）**內挑選下一堂課程：難到需要費力，但又不會超前到你學不會。

儲存強度也是這個 skill 會反駁而不是附和的原因。一個需要**智慧**（現實世界的判斷）的問題，會得到一個嘗試性的回答，接著是一個指向你可以去測試它的社群的指引。這個 skill 不會讓你跳過測驗。一位使用者回報說了「非常感謝」之後，被告知練習還沒結束。

## 課程、參考資料與元件

一堂**課程**是一個自成一體的 HTML 檔，短到一次坐下來就能完成，與使命相關，給你一個具體的成果。它會引用它的來源、推薦一個讓你自己去讀的第一手資料，並連結到兄弟課程與參考文件。

你很少會回頭看課程，但你會回頭看參考文件。所以一堂課程的精簡形式（語法表、演算法、體式序列、詞彙表）屬於 `reference/`，而不是埋在介紹它的那堂課程裡。

課程由 `assets/` 中的**元件**組成：樣式表、測驗小工具、模擬器、圖表輔助工具。重複使用是預設。agent 在撰寫課程之前會先讀 `assets/`，並用那裡已有的東西來組成。任何第二堂課程也可能用到的新東西，它都會寫成元件，而不是內嵌。共用樣式表是每個工作區的第一個元件，它讓課程看起來像一套完整的課程，而不是許多不相關的頁面。

## 常見問題

**它把檔案放在哪裡？我的跑到了 `~/.claude/skills`。**
放在你執行 `/teach` 的那個目錄中（[#377](https://github.com/mattpocock/skills/issues/377)）。

**我要待在同一個 session，還是每堂課程開一個新的？**
三種做法都可以：待在同一個 session、在新的 session 中重新觸發 `/teach`，或在同一個資料夾中開一個新的 session。每一堂課程都是它自己的一次觸發。課程的狀態存在資料夾中，而不是在對話中。常見的做法是在工作區中開一個新的 session，然後說 `/teach next lesson for <topic>`（為 <主題> 上下一堂課）。

**我怎麼知道它教我的不是它編出來的？**
光靠這個 skill 的話，你無法知道。你要去讀第一手資料。`teach` 沒有可靠到可以不經檢查就信任，而任何建立在 LLM 上的 skill 都是如此。它的根據（`RESOURCES.md`、每堂課程中的引用、每堂課程推薦一個第一手資料）讓檢查一堂課程的成本很低。它並沒有消除檢查的必要。這種失敗確實發生過：一位學習 2x2 魔術方塊的使用者，拿到的是編造的、無法解開它的轉法序列。在那種情況下，檢查模型、harness、推理強度設定與來源。在有精確記號的程序性領域中風險最高，在輸出可以立即驗證的地方（例如你可以執行的程式碼）風險最低。

**測驗的正確答案永遠是第一個選項。**
好幾個人在 Sonnet、Opus 與 GLM 上確認過這一點，而它仍然沒有修正。`SKILL.md` 現在要求每個答案的字數都相同。這消除了另一個線索（以前正確答案是唯一完整推理的那一個），但對位置什麼都沒說。一位貢獻者測試了一個針對位置的指示層級修正，結果在九堂課程中，正確答案 33 次中有 33 次仍然落在 A 選項（[#335](https://github.com/mattpocock/skills/issues/335)）。所以真正的修正方式是在 `assets/` 中放一個會洗牌答案的測驗元件，而不是更好的措辭。在那個元件發布之前，忽略答案的位置。你的 `assets/` 目錄是你可以修改的，所以你可以要求一個在渲染時洗牌的元件作為本地修正。

**它假設我已經知道某些東西，還用了它從沒定義過的術語。**
這是最常見的真實抱怨。沒有評估步驟。`teach` 從使命與學習紀錄推斷你的程度，而在第一個 session 中沒有任何學習紀錄。一位在 wayfinder 管線中執行它的使用者直白地說：「它從沒透過拷問來確認我的起點，所以對我已經知道什麼做了很多假設。」另一位回報課程使用了未定義的術語，以及一堂關於他們硬體的課程，涵蓋了那個硬體能做什麼，卻從沒說它不能做什麼。有兩件事有幫助：在第一則訊息中說明你的既有知識與你的不足，並在某堂課程沒抓準時大聲修正程度，因為那個修正會成為一筆學習紀錄，並引導下一堂課程。一個明確的知識評估步驟是一個長期存在的功能請求（[#725](https://github.com/mattpocock/skills/issues/725)），而不是已發布的行為。

**它會做間隔重複嗎？它知道什麼時候該停止教新東西嗎？**
第一個不會，第二個不可靠。這個 skill 圍繞間隔與交錯來設計課程，但沒有任何東西會排程複習，也沒有 Anki 或行事曆的整合。使用者常常要求兩者。一個相關的缺口是結束條件。正如一位使用者所說，`teach`「很會做出下一堂課程，但不太會知道什麼時候該停下來，改為複習或實際練習。」如果你想要複習或操練，而不是新的素材，就直接要求；這個 skill 不會自己提議轉換。

**它只對程式碼有用嗎？**
不是。大部分被回報的使用都在程式設計之外：韓語、日語敬語、鋼琴、吉他、桌遊設計、OpenSCAD、電影情節、Azure 與 CCNA 證照、大學考試，還有八歲和十歲的孩子拿到關於密室逃脫與火蠑螈的可列印小書。這個 skill 中沒有任何東西是程式設計專屬的。使命、資源、近側發展區與操練在任何領域中的運作方式都一樣。在程式碼方面，使用者回報最大的價值來自熟悉一個陌生的程式碼庫或新團隊的技術棧，多於從零開始學一種語言。

**我應該用哪個模型執行它？**
沒有標準答案，而被回報的差異很大。使用者回報較高的[推理強度（reasoning effort）](https://www.aihero.dev/ai-coding-dictionary/effort)比中等設定產出更好的課程。一位使用者透過 Copilot CLI 搭配 Codex 執行同一個 skill，得到的是一張 30 行的 HTML 卡片，而 Claude Code 產出了一堂完整的課程。如果你的組織允許你在 Claude Cowork 中加入 skill，它在那裡可以不經修改直接執行。如果課程出來很單薄，在重寫你的提示之前，先換模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或推理強度。

## 它有效的跡象

- 在一個空目錄中，它做的第一件事是訪問你為什麼想學這個，而不是產出一堂課程。
- `RESOURCES.md` 比課程更早被填滿，而且每堂課程都指名一個值得你自己去讀的第一手資料。
- 課程中的主張帶有外部連結。一堂沒有任何引用的課程，就是這個 skill 在憑記憶教學。
- 一堂課程只需要坐一次，並讓你能做到一件以前做不到的事。
- 在資料夾中開一個新的 session 並說「下一堂課」，會接續課程，而不是重新開始。
- `learning-records/` 持續增長，而課程不再重教你已經展現過的東西。
- 課程看起來像一套完整的課程：它們連結 `assets/` 中的樣式表，而不是每一堂各自帶著自己的。
- 一個需要判斷的問題，會讓你被指向一個論壇、subreddit 或課程，而不只是一個答案。

## 它的定位

`teach` 是一個**隨時都能使用的獨立 skill**。它不是建置鏈中的一步，也不與工程流程共用任何產出物；在你學習這個主題的期間，它都在它自己的目錄中運作。

它唯一真正的鄰居是 [handoff](https://aihero.dev/skills-handoff)。兩者一起回答「如果我在被拷問一件我不懂的事，我該怎麼辦？」不要停下拷問去學習。用 `/handoff` 轉到一個教學工作區，在那裡用 `/teach` 學習這個主題，然後回去從你離開的地方繼續。附近的替代選項是 [research](https://aihero.dev/skills-research)，用於你想要的是一份附引用的文件，而不是課程與長期記憶的時候。當你不確定哪個 skill 或流程適合時，[ask-matt](https://aihero.dev/skills-ask-matt) 會在整套 skill 中為你指路。

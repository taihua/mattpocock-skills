## 它做什麼

`wizard` 產生一個互動式的 bash 腳本，一步一步引導人類完成一個手動程序：接上第三方服務、執行一次性的遷移、把專案從狀態 A 移到狀態 B。它會打開每個 URL、說明要點什麼、複製什麼、擷取回來的值，並把它們寫進 `.env` 檔與 GitHub Actions secrets。

[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 負責寫腳本；它從不執行腳本。執行的是你，在你自己的機器上。精靈是一個程式，而不是一份指示清單。腳本會依序執行每一步，並保存你輸入的值。你的部分只有點擊、貼上和按 Enter。

## 何時使用

你可以輸入 `/wizard`，agent 也可以自己使用它。當它碰到一個你必須親自完成的步驟時（一個它無法產生的金鑰、一個它無法點擊的後台），它會為你建立一個精靈，而不是把指示寫進聊天中，讓它們被捲走。

當下一個卡住你的東西是一趟後台之旅時，就使用它：

| 情況 | 精靈做什麼 |
| --- | --- |
| 一位新開發者在應用程式能啟動之前，需要設定六個服務 | 依序打開每個後台、擷取金鑰，並寫進 `.env` 與 CI |
| 一次性的遷移需要依特定順序切換開關 | 把不可逆的步驟排序並放在確認關卡之後 |
| 一個專案必須一次性地從狀態 A 移到狀態 B | 走過這次轉換，並回報它無法完成的部分 |
| 你正準備把那些步驟寫進 README | 改為寫出一個可執行的版本，當某個步驟過時時，它會明顯地失敗 |

不要用它來*決定*要建什麼；那是 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 與 [to-spec](https://aihero.dev/skills-to-spec) 的工作。

## 前置條件

產生一個精靈不需要任何前置條件。它寫出的精靈在 bash 上執行，並在某個階段要設定 GitHub secret 或 variable 時使用 `gh`。如果缺少 `gh` 或尚未登入，執行並不會失敗。那個階段會顯示一則警告，而最後的總結會告訴你哪些需要手動設定。

## 階段

一個**階段（stage）**是一個螢幕上的一件專注任務。腳本在階段之間會清除終端機畫面，所以一個超出螢幕的階段，會失去被捲走的那一部分。你依相依順序撰寫各個階段，並設定 `TOTAL_STAGES`，它會驅動進度顯示。

[skill](https://www.aihero.dev/ai-coding-dictionary/skill) 在寫任何腳本之前，會先界定程序的範圍。它會讀 repo，而不是憑空發問：`.env*`、`docker-compose*`、框架設定，以及 `.github/workflows/` 中每一個 `secrets.*` / `vars.*` 引用。每一個這樣的引用，都是精靈必須產出的一個值。接著它會給你看排序好的階段清單讓你確認。只有在你確認之後，它才會把每個階段對應到人類要走的確切路徑（「Dashboard → Developers → API keys → Reveal test key → 複製」）。在它不知道目前 UI 的地方，它會問你或查文件，而不是編造點擊步驟。

對於每一個擷取的值，界定範圍時會決定它要去哪裡：

| 目的地 | 何時 |
| --- | --- |
| 只放 `.env` | 本地開發需要它，CI 不需要 |
| GitHub secret | CI 會讀它，而且它是敏感的 |
| GitHub variable | CI 會讀它，而且它是公開的 |
| `.env` 與 secret 兩者 | 本地開發與 CI 都需要它 |
| 哪裡都不放 | 這個階段純粹是一個動作：切換一個開關、升級一個方案 |

## 範本已經解決了使用者體驗

[範本](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)附帶了完整的體驗：附剩餘時間的進度、確認關卡、跨平台開啟 URL（包括 WSL）、隱藏輸入的機密、冪等的 `.env` upsert、`gh secret` / `gh variable` 寫入，以及一份列出所有它必須跳過之項目的最後總結。`STAGES` 標記之上的一切都是固定的函式庫，在每一個精靈中都一模一樣，從不手動編輯。因為函式庫從不改變，每一個精靈的行為都一樣。每個精靈唯一的工作，就是界定程序範圍並撰寫它的各個階段。

寫精靈的 agent 從不從頭到尾執行它，因為腳本會打開瀏覽器並等待人類輸入。agent 改為靜態地檢查它：`bash -n`、可用時執行 `shellcheck`，以及追蹤每個值都落在界定範圍時所說的地方，並且每一個 `set_secret` 的名稱都與 CI 中一個真實的 `secrets.*` 引用相符。所以第一次執行是你的，而那次執行就是測試。

## 預設是短暫的

| 你手上有什麼 | 腳本要怎麼處理 |
| --- | --- |
| 一次性的遷移、個人的設定、一次你永遠不會重複的轉換 | 存到草稿或 `scripts/` 路徑，執行它，刪掉它 |
| 一條 repo 的下一個人也會需要的設定路徑 | commit 它並從 README 連結過去，讓他們執行腳本，而不是再去問一次 agent |

## 常見問題

**我的 API 金鑰最後會進入模型的情境中嗎？**

不會。agent 寫腳本；它不執行腳本。你自己執行腳本，而它以隱藏的終端機輸入擷取金鑰，並直接寫進 `.env` 或 `gh secret`。精靈是一個 CLI，而模型並沒有連到它。這只適用於精靈在執行時擷取的值。如果你在界定程序範圍時把金鑰貼進聊天中，它就會像任何其他貼上的文字一樣進入[情境](https://www.aihero.dev/ai-coding-dictionary/context)。

**我能回頭修正一個打錯的值嗎？**

執行中途不行。沒有返回鍵。階段只會往前走，在第 3 階段答錯就代表要按 Ctrl-C 然後重新執行。重新執行很便宜，因為任何已經寫進 `.env` 的值都會作為預設值再提供一次，所以你在答對的階段直接按 Enter，只重新輸入錯的那一個。使用者在發布那一週就要求了這個功能，而它至今仍然開放：「超愛！不過有一點，有沒有辦法回頭修正你輸入的東西？」

**它知道我已經設定了什麼嗎？**

部分知道，而且比發布時人們的反應所假設的要少。它在詢問之前會先讀 repo（你的 `.env` 檔、`docker-compose`、框架設定、CI 中的 `secrets.*` 引用），所以它界定的範圍是缺少的值，而不是像 README 那樣從零開始。它不做的是檢查第三方服務。如果一個金鑰存在於你的 `.env` 中，精靈會把它提供回來，按 Enter 就保留；如果你已經建立了 Stripe 帳號，但從沒存下金鑰，精靈仍然會把你送到後台去取它。

**它在工作流程中位於哪裡，在拷問與 spec 之後嗎？**

沒有特定的位置。它是一個獨立的 skill，而不是鏈中的一步。常見的猜測是 `/grill-with-docs → /to-spec → /wizard`，那個順序也沒問題，但觸發條件是一個手動程序出現了，而這可能發生在任何時間點：開始之前、建置中途，或交付很久之後。它也可以作為一個探索工具。界定範圍會找出一個任務隱藏的前置條件，例如你沒想到的三個 API 金鑰，讓你在投入工作之前就知道。

**它在 Claude Code 之外也能運作嗎？**

腳本可以。它是純 bash，不論是哪個 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 產生的，執行起來都一樣。skill 本身是模型觸發的，所以在每個地方都會被列出：在 Claude Code 中輸入 `/wizard`，在 Codex 中輸入 `$wizard`，或直接描述你卡住的設定。模型觸發也讓它避開了 [#693](https://github.com/mattpocock/skills/issues/693)，在那個問題中，Claude 的桌面與網頁應用程式會把*使用者觸發*的 skill 從[模型](https://www.aihero.dev/ai-coding-dictionary/model)的清單中拿掉，並回報它們沒有安裝。

**它以前不是使用者觸發的嗎？**

以前是。現在它是模型觸發的，所以 agent 碰到一個你必須親自完成的步驟時，會在沒有提示的情況下使用它。你以前能做的事，沒有任何一件停止運作。模型觸發讓 agent 和你都能呼叫這個 skill，所以 `/wizard` 的行為和以前一樣。這個改變修正了一個失敗。以前，一個在建置中途碰到憑證關卡的 agent，會在聊天中丟出六個編號步驟讓你手動照做。現在它會寫一個精靈。

**它以前在 `in-progress/` 中。現在在哪？**

從 v1.2 開始在 `engineering/`。它從 beta 分類畢業，現在隨 plugin 一起發布，所以它會和其他推廣的 skill 一起出現，而不需要個別安裝。它的行為在畢業時沒有改變。

## 它有效的跡象

- 在任何腳本存在之前，你會看到一份排序好的階段清單，以及每個階段產出的值，並被要求確認。
- 每一個 URL 都在詢問該頁面上的值之前被打開。你從不會被要求貼上一個你還沒被送去取得的東西。
- 機密是盲打的。沒有任何敏感資訊會回顯到你的捲動紀錄中。
- 每個階段都放得進一個螢幕。沒有任何你還需要的東西被捲走。
- 按 Ctrl-C 再重新執行，會從你離開的地方接續，並把已經存下的值作為預設值提供。
- 最後的畫面列出它寫了什麼，並另外列出它無法完成、需要你手動完成的事。

## 它的定位

`wizard` 是一個隨時都能使用的獨立 skill，位於自動化停止、人類必須點擊的那條線上。它最近的鄰居是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，因為兩者存在的目的都是讓 repo 進入可運作的狀態。那一個設定這套 skill，而 `wizard` 為其他一切產生設定路徑。它也與 [implement](https://aihero.dev/skills-implement) 搭配：當一次建置落地了一個需要憑證或手動切換的功能時，精靈會涵蓋那些只有人類能做的步驟。當你不確定哪個 skill 適合當下時，[ask-matt](https://aihero.dev/skills-ask-matt) 會幫你指路。

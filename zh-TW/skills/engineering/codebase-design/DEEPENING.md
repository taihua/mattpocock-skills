# 加深（Deepening）

在考量依賴的前提下，如何安全地加深一群淺模組。假設你已了解 [SKILL.md](SKILL.md) 中的詞彙：**module**、**interface**、**seam**、**adapter**。

## 依賴的類別

評估一個加深候選對象時，先把它的依賴分類。類別決定了加深後的模組要如何跨越它的接縫進行測試。

### 1. 程序內（In-process）

純計算、記憶體內狀態、沒有 I/O。永遠可以加深：合併這些模組，直接透過新的介面測試。不需要 adapter。

### 2. 可在本地替代（Local-substitutable）

有本地測試替身的依賴（用 PGLite 替代 Postgres、記憶體內的檔案系統）。如果替身存在，就可以加深。加深後的模組在測試套件中搭配替身執行測試。接縫是內部的；模組的外部介面上沒有 port。

### 3. 遠端但自有（Ports & Adapters）

跨越網路邊界的自有服務（微服務、內部 API）。在接縫上定義一個 **port**（介面）。深模組擁有邏輯；傳輸層以 **adapter** 的形式注入。測試使用記憶體內的 adapter。正式環境使用 HTTP / gRPC / 佇列 adapter。

建議的形式：*「在接縫上定義一個 port，為正式環境實作一個 HTTP adapter，為測試實作一個記憶體內的 adapter，這樣即使它部署在網路的兩端，邏輯仍然集中在一個深模組中。」*

### 4. 真正的外部服務（Mock）

你無法控制的第三方服務（Stripe、Twilio 等）。加深後的模組以注入的 port 接收外部依賴；測試提供一個 mock adapter。

## 接縫的紀律

- **一個 adapter 代表假想的接縫。兩個 adapter 才代表真正的接縫。** 除非至少有兩個 adapter 是合理的（通常是正式環境 + 測試），否則不要引入 port。只有一個 adapter 的接縫只是多一層間接。
- **內部接縫 vs 外部接縫。** 深模組可以有內部接縫（實作私有、給它自己的測試用），以及位於介面上的外部接縫。不要只因為測試用到了內部接縫，就把它們透過介面暴露出去。

## 測試策略：替換，而不是疊加

- 一旦在加深後模組的介面上有了測試，針對原本淺模組的舊單元測試就變成廢物了；刪掉它們。
- 在加深後模組的介面上寫新的測試。**介面就是測試面（test surface）**。
- 測試透過介面斷言可觀察的結果，而不是內部狀態。
- 測試應該能撐過內部重構，因為它們描述的是行為，而不是實作。如果實作改變時測試也必須改，代表它測試的範圍越過了介面。

# 設計兩次（Design It Twice）

當使用者想為某個已選定的加深候選對象探索替代介面時，使用這個平行子代理的模式。基於 Ousterhout 的「Design It Twice（設計兩次）」：你的第一個想法不太可能是最好的。

使用 [SKILL.md](SKILL.md) 中的詞彙：**module**、**interface**、**seam**、**adapter**、**leverage**。

## 流程

### 1. 框定問題空間

在派出子代理之前，為選定的候選對象寫一段面向使用者的問題空間說明：

- 任何新介面需要滿足的限制
- 它會依賴的東西，以及這些依賴屬於哪個類別（參見 [DEEPENING.md](DEEPENING.md)）
- 一段粗略的示意程式碼草圖，用來讓限制變得具體，不是提案，只是讓限制看得見的方式

把這些給使用者看，然後立刻進行步驟 2。使用者在子代理平行工作的同時閱讀與思考。

### 2. 派出子代理

平行派出 3 個以上的子代理，每個都使用全新的 context window。每一個都必須為加深後的模組產出一個**截然不同**的介面。

給每個子代理一份獨立的技術簡報（檔案路徑、耦合細節、來自 [DEEPENING.md](DEEPENING.md) 的依賴類別、接縫後面放了什麼）。這份簡報與步驟 1 中面向使用者的問題空間說明是分開的。給每個 agent 一個不同的設計限制：

- Agent 1：「最小化介面：最多 1 到 3 個進入點。最大化每個進入點的槓桿。」
- Agent 2：「最大化彈性：支援許多使用情境與擴充。」
- Agent 3：「針對最常見的呼叫者最佳化：讓預設情況變得簡單到不行。」
- Agent 4（如果適用）：「針對跨接縫的依賴，圍繞 ports & adapters 來設計。」

在簡報中同時包含 [SKILL.md](SKILL.md) 的詞彙與 GLOSSARY.md 的詞彙，讓每個子代理的命名都與架構語言和專案的領域語言一致。

每個子代理輸出：

1. 介面（型別、方法、參數，加上不變式、順序、錯誤模式）
2. 使用範例，展示呼叫者如何使用它
3. 實作在接縫後面隱藏了什麼
4. 依賴策略與 adapter（參見 [DEEPENING.md](DEEPENING.md)）
5. 取捨：哪裡槓桿高、哪裡槓桿薄

### 3. 呈現與比較

依序呈現各個設計，讓使用者能逐一消化，然後用文字比較它們。從**深度（depth）**（介面上的槓桿）、**局部性（locality）**（變更集中在哪裡）與**接縫位置**來對照。

比較之後，給出你自己的建議：你認為哪個設計最強，以及為什麼。如果不同設計的元素可以很好地結合，就提出一個混合方案。要有主見：使用者想要的是一個明確的判斷，而不是一份菜單。

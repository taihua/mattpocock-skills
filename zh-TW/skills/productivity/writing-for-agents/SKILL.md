撰寫任何 agent 會讀取的文件時的參考：skill、`AGENTS.md` / `CLAUDE.md`、透過指標讀到的文件。包裝方式不同，寫法則相同：同樣的槓桿能讓每一種都可預測，因為 agent 每次執行時走的是相同的*流程*，而不是產出相同的輸出。

如果你正在撰寫的文件是一個 skill，請閱讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、觸發方式的選擇以及路由 skill。

## 情境指標（Context pointers）

**情境指標**是存在於 agent 情境（context）中的一個引用，它指名某份不在情境中的資料，並編碼了「何時該去讀取它」的條件。skill 的 description 就是一種；`AGENTS.md` 中指名某份文件的一行字也是同樣的東西。決定 agent 何時去讀取該資料、以及多可靠地讀取的，是指標的*措辭*，而不是它指向的目標。一個必要的目標卻配上措辭薄弱的指標，就是一個變異性（variance）bug：先把措辭磨利，只有在磨利失敗時，才把資料直接內嵌進來。

指標有兩項工作：說明這份資料是什麼，並列出應該觸發讀取它的**分支（branch）**（分支是指文件所處理的一種獨特情況，所以不同次的執行會走過不同的路徑）。一個永遠載入的指標，每個字在每一輪都要付出成本，因此它比本文更需要嚴格刪減：

- **把主導詞放在最前面**：指標就是它發揮觸發作用的地方。
- **每個分支一個觸發詞。** 為同一個分支換個說法的同義詞，等於把一個分支寫了兩次；把它們合併，只保留真正不同的分支。
- **刪掉本文已經表達的身分說明。**

## 兩種負擔

你加入的每一份文件和每一個指標，都會花費兩種預算之一：

- **情境負擔（Context load）**是永遠載入的資料對 agent 視窗造成的成本：`AGENTS.md` 中的一行、一個 skill 的 description、任何每一輪都留在情境中的東西，不論是否被觸發，都在花費 token 與注意力。
- **認知負擔（Cognitive load）**是對人類造成的成本：有哪些文件存在，以及何時該使用每一份。人類就是索引。這不是要最小化的成本：它是人類主導權的代價；在需要人類判斷的地方花費它，在不需要的地方移除它。

只透過指標觸及的資料，可以用指標本身那一行的代價躲過情境負擔；完全沒有指標的資料，則完全依賴認知負擔。

## 資訊層級（Information hierarchy）

一份文件由兩種內容組成：**步驟（steps）**（agent 依序執行的動作）和**參考（reference）**（依需要查閱的定義、規則、事實）。兩者可以自由混合：全部是步驟（一份食譜）、全部是參考（一份審查規則、這個 skill 本身），或兩者都有。核心的決策是每一部分要放在**資訊層級**的哪個位置，這是一個依「agent 多迫切需要這份資料」排序的階梯：

1. **檔案內的步驟**是最主要的一層：agent 依序要做的事。
2. **檔案內的參考**依需要查閱。通常是合理的扁平同級集合（一份審查的每一條規則都在同一階），這是很好的安排，不是壞味道。
3. **揭露式參考（Disclosed reference）**被移出到另一個檔案，透過情境指標觸及，只在指標被觸發時才載入。範圍從同一資料夾中的兄弟檔案，到放在任何地方、任何文件都能指向的完全外部參考。

往下移得太少，頂層就會臃腫；往下移得太多，又會把 agent 真正需要的資料藏起來。這個拉扯就是整個決策的核心。

**漸進式揭露（Progressive disclosure）**是沿著階梯往下移（移出主檔案、放到指標後面），讓頂層保持易讀。它主要不是為了節省 token：它是保護層級結構的方式。分支是最乾淨的揭露判準：每個分支都需要的就內嵌，只有部分分支會用到的就放到指標後面。當一份文件有步驟時，本該被揭露的檔案內參考會把步驟埋沒，讓 agent 是否注意到它們變成擲銅板：這是一個變異性槓桿，不只是易讀性的問題。

**共置（Co-location）**是檔案內的搭檔：階梯決定一部分要放*多低*，共置則決定它到了那裡之後*旁邊放什麼*。把一個概念的定義、規則和注意事項放在同一個標題下，而不是四處分散，這樣讀到其中一部分時，相鄰的部分也會一起被讀到。判準：文件讀起來應該像是為 agent 寫的說明文件。分組的資料讀起來是這樣；分散的資料則不是。（這與重複不同：重複是把同一個意思放在兩個地方；分散則是把同一個意思拆成碎片散在很多地方。）

**蔓生（Sprawl）**是這裡的失敗模式：一份文件就是太長了，即使每一行都還有效、都不重複。注意力在多餘的部分中被稀釋，每多一行就多一行需要保持相關。解法就是階梯：把參考揭露到指標後面，並依分支或順序拆分，讓每條路徑只帶它需要的東西。

## 步驟與完成條件

每一個步驟都以一個**完成條件（completion criterion）**作結，也就是告訴 agent 工作已完成的條件。有兩個特性讓它成為槓桿：

- **清晰度**：agent 能分辨完成與未完成嗎？模糊的界線（「已達成理解」）會招致**過早完成（premature completion）**：在真正完成之前就結束這一步，注意力滑向*完成這件事本身*。前方仍可見的步驟（**完成後的步驟**）提供拉力；條件的清晰度則是阻力。依序防守：**先磨利界線**（局部且便宜）；只有在它本質上無法避免模糊、*而且*你確實觀察到 agent 在趕時，才透過拆分順序把後面的步驟藏起來。隱藏只有跨越真正的情境邊界時才有效（交接或派出子代理；在同一處直接呼叫的話，後面的步驟仍留在情境中，什麼也沒清掉）。
- **要求程度**：它要求多少。「每一個被修改的 model 都有交代」會逼出徹底的工作，「產出一份變更清單」則不會。要求程度驅動**跑腿工作（legwork）**（agent 在工作中進行的挖掘，潛藏在措辭中，而不是寫成獨立的步驟），而且它不受步驟限制：「每條規則都套用過」約束一整份扁平參考的方式，就跟「每個步驟都完成」約束一段順序一樣，這就是一份全是參考的文件仍能帶有完整性標準的方式。

最強的條件既可檢查，又具完整性。

## 何時拆分

把一份文件拆成兩份，會花費兩種負擔之一，所以只有在這一刀值得時才拆：

- **依順序**：當完成後的步驟會誘使 agent 趕著做完眼前這一步時，就拆開一串步驟。讓它們不在視線內，能為當前任務驅動更多的跑腿工作。要小心反向的情況：合併順序會讓每一步都看見後面的步驟，招致過早完成。
- **依觸發方式**，skill 專屬：參見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主導詞（Leading words）

**主導詞**是一個已經存在於模型預訓練中的精簡概念，agent 在執行文件時會用它來思考（_lesson（課程）_、_fog of war（戰爭迷霧）_、_tracer bullets（曳光彈）_）。它以 token 的形式重複出現，而不是一整句話，藉此累積出一個分散式的定義，並借用模型已有的先驗知識，以最少的 token 錨定一整區的行為。自創詞彙也行，前提是你清楚定義它，但自創的詞不會借用任何先驗：預訓練詞彙免費給你的東西，你得用定義的 token 來付；優先找一個現成的詞。

它錨定兩次。在本文中是*執行*：每次這個詞出現時，agent 都會採取相同的行為，而在扁平的參考中，它會把注意力集中在某一類要找的東西上。在指標中是*觸發*：當同一個詞出現在你的提示、你的文件和你的程式碼庫中時，agent 會把這套共用語言與資料連結起來，更可靠地觸及它。

主動尋找可以用主導詞重構的機會。在三個地方寫出來的三件組，或花一整句話去比劃一個概念的指標。每一個都是迫切想被濃縮成單一 token 的段落：

- 「快速、確定性、低開銷」→ _tight（緊密）_（一個 _tight_ 迴圈）。
- 「一個你相信的迴圈」→ _red（紅燈）_，把一個模糊的關卡變成一個二元、可觀察的狀態（迴圈在這個 bug 上變成 _red_，或者沒有）。

你贏兩次：更少的 token，以及一個讓 agent 掛上思考的更銳利的鉤子。假設每份文件都帶著可以被主導詞取代的重述。去把它們找出來。

**否定（Negation）**是這個槓桿旁邊的失敗模式：用禁止來引導，會把被禁止的行為拉進情境中，讓它*更*容易出現，而不是更少。_不要想一頭大象_，結果腦中只剩下大象；否定是一個弱修飾詞，會被強烈活化的概念蓋過，所以這個禁令有一半會被讀成「去做那件事」的指示。提示**正向**的內容：說明目標行為（「寫一行的註解」），讓被禁止的行為根本不會被說出口。只有當它是一條你無法用正向方式表達的硬性護欄時，禁止才值得存在；即使如此，也要搭配正向的目標，讓注意力落在該做的事情上。

## 刪減（Pruning）

- 讓每個意思只有一個**單一事實來源（single source of truth）**：一個權威的位置，這樣改變行為只需要改一個地方。**重複（Duplication）**（同一個意思出現在不只一個地方）會耗費維護成本和 token，並把這個意思在階梯上的顯著程度膨脹到超過它真正的位階。（這是主導詞意外的反面：主導詞是刻意重複一個 token，而從不重複意思。）
- **環境**也是一個事實來源（`package.json` 的 scripts、設定檔、目錄結構、`--help` 的輸出），而一份重述它的文件就是一個**快取（cache）**：一次查詢結果的副本，只有在查詢成本很高時才值得它的負擔。快取那些 agent 無法透過查看找到的東西：不成文的慣例、某個選擇背後的理由、任何設定檔都不會告訴你的陷阱。把那些看一個檔案、跑一個指令就能查到的東西留給環境，在那裡它們不會過時。
- 檢查每一行的**相關性**：它還與這份文件要做的事有關嗎？一行字會因為從未與任務相關（純粹的說明，或是本該被揭露的分支）而失去相關性，也會因為它所描述的行為或世界改變而過時。越短的文件越容易保持相關。沒有刪減的紀律，預設的命運就是**沉積（sediment）**：過時的層層堆積，因為新增感覺安全、移除感覺有風險，直到你必須鑽探穿過它們才能找到仍然有效的部分。
- 逐句尋找**無作用指令（no-op）**：一個模型預設就會遵守的指令，付了負擔卻什麼也沒說。判準（相較於預設，它有沒有改變行為？）是相對於模型，而不是相對於讀者：兩個人對某句是否為 no-op 意見不同，其實是對預設行為意見不同，要透過實際執行文件來解決，而不是靠辯論。當一句話不合格時，刪掉整句，而不是刪減其中幾個字。這個判準也用來評估主導詞：一個太弱、敵不過預設的詞（當 agent 本來就算徹底時說 _be thorough（要徹底）_）就是 no-op，解法是換一個更強的詞（_relentless（毫不留情）_），而不是換一種技巧。

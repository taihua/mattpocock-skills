# MISSION.md 格式

`MISSION.md` 放在工作區的根目錄。它記錄使用者學習這個主題的*理由*。每一個教學決策（接下來教什麼、要提供哪些資源、要設計哪些練習）都應該能追溯回這份文件。

## 範本

```md
# Mission: {主題}

## Why（為什麼）
{1 到 3 句話。使用者追求的具體現實目標。當他擁有這項技能後，他的生活或工作會有什麼改變？避免「為了理解 X」這種抽象說法；要追問背後真正的成果。}

## Success looks like（成功的樣子）
- {一件使用者將能做到、具體且可觀察的事}
- {另一件具體的事}
- {…}

## Constraints（限制）
- {時間、預算、既有承諾、學習偏好，以及任何會限制做法的條件}

## Out of scope（範圍外）
- {使用者明確表示目前不想追的相鄰主題，用來保護近側發展區}
```

## 規則

- **一個工作區只有一個使命。** 如果使用者想學兩件無關的事，那就是兩個工作區。
- **具體勝過抽象。** 「十月前跑完半馬」勝過「變得更健康」。「交付一個 Rust CLI 給我的團隊」勝過「學 Rust」。
- **對模糊的說法提出反駁。** 如果使用者說不出為什麼，在寫任何東西之前先訪問他。一個糟糕的使命比沒有使命更糟。
- **現實改變時就修訂。** 使命會變。當使用者的目標移動時，更新這個檔案：不要讓過時的使命繼續引導未來的課程。
- **保持簡短。** 如果 `MISSION.md` 超過一個螢幕，它就不再是指南針，而開始變成一份計畫了。

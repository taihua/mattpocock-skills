# 學習紀錄格式

學習紀錄存放在 `./learning-records/`，採用流水編號：`0001-slug.md`、`0002-slug.md` 等等。目錄採延遲建立：只有在寫下第一筆紀錄時才建立。

它們是教學版的 ADR（架構決策紀錄）：記錄不明顯的心得、關鍵洞見，以及使用者自述的既有知識，這些都會引導未來的課程。它們被用來推算近側發展區（zone of proximal development）。

## 範本

```md
# {學到或確立了什麼的簡短標題}

{1 到 3 句話：學到了什麼（或確立了哪些既有知識），以及為什麼這對未來的課程很重要。}
```

這就是完整的格式。一筆學習紀錄可以只有一段話。它的價值在於記錄「這件事*現在*已經知道了」以及「*為什麼*這會改變下一步要教什麼」，而不是把各個段落填滿。

## 選用段落

只有在真正有價值時才加入。大多數紀錄都不需要。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：當早先的理解後來被證明是錯的並被取代時很有用。
- **Evidence（證據）**：使用者如何展現他的理解（回答了某個問題、完成了某個練習、引述了過去的經驗）。當這項主張之後可能被重新檢視時很有用。
- **Implications（影響）**：這為未來的課程開啟或排除了什麼。在不明顯時值得記錄。

## 編號

掃描 `./learning-records/` 找出目前最大的編號，然後加一。

## 何時寫學習紀錄

只要符合以下任一條件就寫一筆：

1. **使用者對某件不簡單的事展現了真正的理解**：不只是接觸過，而是有證據顯示他能正確運用這個概念。這為接下來要教的內容設定了新的底線。
2. **使用者透露了既有知識**：「我已經會 X 了。」記錄下來，讓未來的課程不會重教。也要記錄他所聲稱的*深度*。
3. **修正了一個誤解**：使用者先前相信某件錯的事，現在明白了原因。這類紀錄價值很高：它們能預測相關主題未來的絆腳石。
4. **使命因為學習而改變**：使用者發現自己在意的東西和原本以為的不同。交叉連結到 [[MISSION.md]] 並更新它。

### 什麼*不*算

- 只是被講過的內容。講過不等於學會。要等到有證據。
- 已經以術語定義的形式簡潔記錄在 [[GLOSSARY.md]] 中的內容。不要重複。
- 逐次課程的活動日誌。學習紀錄不是日記：它們是足以作為決策依據的洞見。

## 取代（Supersession）

當較新的紀錄與較舊的紀錄矛盾時（使用者的理解加深或被修正），把舊紀錄標記為 `Status: superseded by LR-NNNN`，而不是刪除它。理解如何演進的歷史本身就是有用的訊號。
